# Hangcha StockCount — 年度盘库管理 v0.5.0

手机端仍为原始 v0.4.4（未修改）。新增 Windows 管理端，用于合并多个员工导出、解决冲突、复制原库存工作簿并重建库存。

## 安装与使用

1. Windows 安装 Python 3.10+ 和桌面版 Microsoft Excel；双击 `desktop/启动管理员工具.bat`。首次启动若缺少 pywin32，将尝试安装（需要网络）。无需服务器。
2. 点击「导入库存表」，选择盘库开始前冻结的 `.xlsx` 或 `.xlsm`；输入工作表精确名称、表头行、ERP、Part No.、存及可选库位/名称表头。必须是唯一表头，不要求固定列顺序。请关闭正在编辑的源表。原表须已正确计算，且每个零件的存为整数公式。不要使用已含本次归零/入库列的输出作为源表。
3. 如需发放新手机基准，点击「生成手机基准」。已有手机导出的旧基准 ID 可以使用，但生成时需人工确认对应的确实是同一冻结库存表。
4. 点击「导入员工 JSON」，多选所有员工的最终完整文件。允许补充导入；相同 ID 取最新版本，最新删除状态排除；相同 ID 同时刻但内容不同、多个批次/基准混合时停止。保留每位员工最终导出，旧文件不能推断后来已删除的记录。
5. 点击「仅显示待处理」，逐条处理冲突。双击或点击「确认/修改选中记录」：指定目标 Excel 行、数量、实际库位及处理依据；可批量排除重复记录并填写原因。相同零件不同且不重叠的库位自动累加；相同或前缀重叠的库位需要确认。不同零件同库位可正常共存。ERP 与 Part No. 同时存在时须唯一且一致匹配；不一致不自动匹配。确认后仍可撤销决定。新导入的记录如与已有记录重叠，会将尚未确认的记录标为待处理。
6. 「保存项目」保存源文件哈希、输入路径、人工决定；「打开项目」恢复。项目文件不内嵌原文件，请保持输入文件路径与内容，保留备份。记录内容改变时原决定不复用。
7. 查看「未盘点零件清单」。未盘点不等于没有库存：只有管理员明确确认后才按 0 处理。所有冲突须解决；确认全部员工已提交、盘库期间出入库已冻结。
8. 点击「生成新库存表」，选择是否更新库位，指定不存在的新文件名。原工作簿以只读方式打开，使用 Excel 自己的 SaveCopyAs 保存副本；两列追加在原表已使用区域右侧，避免移动原有列。原表绝不覆盖。输出旁生成 `.audit.json`，记录来源、删除状态、确认依据、汇总数量。

## 库存公式规则

- 盘库前归零 = -盘库前存（静态整数，包括原库存为负的情况）。
- 盘库入库 = 合并确认的实际数量（静态整数）。
- 新存公式 = `(原公式表达式)+归零单元格+盘库入库单元格`。
- Excel 强制重算，逐行验证存等于确认数量，校验失败不发布新库存表。
- 如选更新库位，仅对有有效盘库记录的行使用正数量记录的实际库位（多个以 `/` 连接）；无有效记录的行保留原库位。尺寸、重量、名称、成本等原字段不自动覆盖。

## 当前边界（试用版）

- 本次提供的原始文件没有 desktop 源码及正式库存 Excel，因此这是独立重建的管理端，而非原管理端补丁。Windows Excel COM 真实工作簿读写、图形界面尚未在目标机器验收。
- 尚未自动新增未知零件行：先在盘库前原表的独立副本中由管理员建立正确 ERP/Part No.、成本及存公式（不改变原有零件的冻结库存），再将该副本作为新基准重新导入；手机基准 ID 不同须核对。不得为了通过冲突而随意匹配已有零件。
- 对表格（ListObject）的新增列不自动扩展表格范围；源表复杂结构、跨行公式、外部链接、宏、保护、汇总行、筛选范围等须用真实表验收。原有库存成本等公式保留，但未逐项验证业务结果。Excel 打开外部链接时禁用自动更新，宏禁用。
- 归零列与入库列采用追加位置；HCE Oracle 是否能识别并保持新公式必须另外验证。不要直接用于正式库存，先对副本试运行。
- 项目、盘库记录、基准 JSON、生成 Excel 和审计文件属于内部数据，不要上传公开 GitHub 仓库。

## 测试

在 desktop 下运行 `py -3 -m unittest -v`。10 项纯 Python 测试覆盖版本去重、删除、同时刻冲突、批次/基准、编号冲突、未知零件、不同库位累加、库位重叠及人工确认、非法数量。另通过 Python 编译与原手机 app.js 语法检查。测试不替代 Windows Excel 实际验收。
